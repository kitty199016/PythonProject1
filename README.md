# PythonProject1: Система учёта товаров и категорий

Проект представляет собой базовую структуру данных для управления каталогом товаров интернет-магазина или склада. Код написан на языке Python с соблюдением стандартов оформления **PEP 8**.

## 📋 Описание моделей

В модуле `src/models.py` реализованы два основных класса:

### 1. `Product` (Товар)
Класс для представления отдельной единицы товара.
* **Свойства объекта:**
  * `name` (str) — название товара.
  * `description` (str) — детальное описание.
  * `price` (float) — стоимость товара.
  * `quantity` (int) — количество единиц в наличии.
* **Атрибуты класса:**
  * `product_count` — автоматически подсчитывает общее количество созданных уникальных товаров.

### 2. `Category` (Категория)
Класс для группировки товаров по категориям.
* **Свойства объекта:**
  * `name` (str) — название категории.
  * `description` (str) — описание категории.
  * `products` (list) — список объектов класса `Product`, входящих в эту категорию.
* **Методы:**
  * `add_product(product)` — добавляет объект товара в список `products`.
* **Атрибуты класса:**
  * `category_count` — автоматически подсчитывает общее количество созданных категорий.

## ✨ Новые архитектурные возможности (Текущий этап)

В рамках выполнения текущего задания архитектура проекта была переведена на принципы ООП с использованием абстракции и множественного наследования:

### 1. Абстрактный базовый класс (`BaseProduct`)
* Реализован базовый класс `BaseProduct` (на основе модуля `abc`), который задает обязательный контракт для всех видов товаров в магазине.
* Все сущности (`Product`, `Smartphone`, `LawnGrass`) обязаны реализовывать инициализацию базовых атрибутов, строковое представление (`__str__`) и логику сложения остатков стоимости (`__add__`).
* Прямое создание объектов класса `BaseProduct` запрещено на уровне интерпретатора.

### 2. Класс-миксин для логирования (`LogMixin`)
* Разработан миксин `LogMixin`, автоматически логирующий создание каждого объекта в системе.
* При инициализации любого товара (включая наследников) в консоль мгновенно выводится сообщение в формате:  
  `Создан объект: ИмяКласса('Название', 'Описание', Цена, Количество)`
* Миксин интегрирован в цепочку множественного наследования (`MRO`) перед базовыми классами, обеспечивая безопасную передачу аргументов.

### 3. Строгая валидация типов при сложении
* Метод сложения товаров `__add__` переведен на проверку точных типов с помощью функции `type()`.
* Теперь складывать общую стоимость на складе можно **только для товаров абсолютно одного класса** (например, смартфон можно сложить только со смартфоном, но нельзя сложить со стандартным продуктом или газонной травой). При попытке смешивания выбрасывается ошибка `TypeError`.

### 🛠 Что нового:

#### 1. Инкапсуляция и управление ценами в `Product`
* **Приватность данных**: Атрибут цены товара переведен в приватный режим (`__price`). Прямой доступ к нему снаружи класса защищен.
* **Геттер `price`**: Позволяет безопасно получать текущую стоимость товара.
* **Сеттер `price`**: Реализует валидацию вводимых данных. При попытке установить цену, равную или меньшую нуля, в консоль выводится предупреждение: `“Цена не должна быть нулевая или отрицательная”`, а старое значение цены сохраняется.

#### 2. Строковое представление товаров в `Category`
* Свойство `products` класса `Category` теперь возвращает отформатированную строку со списком всех товаров в формате:
  `Название товара, X руб. Остаток: Y шт.`

### 🧪 Тестирование и отчетность

Для проверки корректности работы написаны автоматические тесты на фреймворке `pytest`.

#### Что проверяют тесты:
* Корректность инициализации объектов и их атрибутов.
* Работу приватного атрибута цены (проверка вызова `AttributeError` при попытке прямого доступа).
* Валидацию цен сеттером (проверка работы с корректными, нулевыми и отрицательными значениями).
* Перехват консольного вывода (`capsys`) для валидации предупреждений.
* Изоляцию тестов за счет автоматического сброса глобальных счетчиков классов перед каждым запуском.

#### 📊 Генерация визуального HTML-отчета

Для формирования наглядного интерактивного отчета о прохождении тестов используется плагин `pytest-html`.

**Запуск тестов с генерацией отчета:**
```bash
# Для стандартного окружения (pip/venv):
pytest --html=report.html --self-contained-html

# Для проектов под управлением Poetry:
poetry run pytest --html=report.html --self-contained-html
```

После выполнения команды в корне проекта создается автономный файл **`report.html`**, который можно открыть в любом браузере для анализа результатов тестирования.
